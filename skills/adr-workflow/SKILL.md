# ADR 总控

本组件仅面向软件项目开发中的 ADR 决策链，负责意图识别、顺序、交接和停点；不是通用写作或文档处理入口。四个功能组件均可单独调用；用户明确指定其中一个时，直接让该组件成为当前主入口，不因总控存在而自动执行整条链。普通文案、报告、资料整理或仅修改一般文档，即使出现“ADR”字样，也不触发本总控。

完整流程需要 `adr-check`、`adr-writing`、`adr-review` 和 `adr-implementation` 及其资料。将五个 Skill 安装在同一个 Skills 父目录；某阶段所需组件或资料不可读取时，说明缺失项并停止该阶段，不把缺失的工作记为通过。

## 识别请求

| 用户意图 | 选择 |
|---|---|
| “检查哪些模块会过载”“为 ADR 看现有代码职责” | 只用 `adr-check` |
| “为这个软件功能讨论/写/修订 ADR 并完成方案审查”，未授权实施 | 必要时 `adr-check`，再 `adr-writing` 与独立 `adr-review`；到方案门禁结束 |
| “独立审查这份 ADR 的方案” | 只用 `adr-review`，不代作者修改 |
| “按这份已确定 ADR 实施/继续第 N 阶段” | 只用 `adr-implementation`；先核对决策、审查和权限，不重写已通过阶段 |
| “从需求写 ADR 并直接落地”“完整一条龙” | `adr-check → adr-writing → adr-review → adr-implementation`，在已授权范围内连续推进 |

若开发请求只给出含糊的“看看 ADR”，先确定是规划、审查还是实施；不能从含糊措辞推定代码或外部操作授权。无代码影响的 ADR 可把架构检查标记“不适用”并说明理由。用户明确限定某阶段或只要草案时，不启动后续阶段；单纯要求写 ADR 草案由 `adr-writing` 独立处理。

## 组装规则

交接时引用同一份范围基线：目标、非目标、既有能力复用、旧行为不变量、完成条件，以及用户后续已授权变化及来源；使方案审查和每轮实施审查都能核对累计范围，不重复建立状态文档。

1. 当前阶段只加载一个主组件；切换阶段时传递最小交接包：用户目标与原始来源锚点、代码身份、ADR/架构影响报告/阶段/测试记录的相对位置、当前审查输入指纹、方案审查轮次与结论、已完成证据、剩余范围和授权边界。引用项目唯一事实所有者，不再建第二份进度表。
2. 写 ADR 前，对受影响的代码取得 `adr-check` 的证据；主智能体按 `adr-writing` 完成用户选择、方案、合同及[作者自查与修订](../adr-writing/SKILL.md#作者自查与修订)，不增加独立流程节点。
3. 主智能体依 [审查输入指纹规则](../adr-review/references/input-fingerprint.md) 固定受检版本，填充 `adr-review` 的任务模板，交给独立人员或具有独立上下文的代理只读审查，再接收结论与定位意见。审查者不得是方案撰写者，并须自行复算指纹。主智能体将每轮结果、受检指纹及意见处置写入独立审查记录；有实质意见则按 `adr-writing` 职责修订 ADR，并对新版本复审。默认一轮，最多两轮；轮次持续保存，不因续行或换审查者重置。独立审查缺席或第二轮仍未通过时，ADR 保持 `PROPOSED`，向用户呈现具体缺口并停止，主智能体不得自行宣布通过或默认免审。
4. 主智能体仅在审查 `PASS` 对应当前 ADR、阶段计划及测试合同的有效指纹，重大待决项已关闭且用户明确授权实施时记录“可实施”门禁。审查结论与就绪状态保存在独立审查记录；项目要求修改 ADR 状态字段时按指纹规则记录机械变更，不凭过期 `PASS` 进入 `adr-implementation`。若实施中发现必须改变持久合同或产品决定，按阶段门禁记录影响后返回写作与方案审查，不用代码悄悄改变 ADR。旧的已接受 ADR 不因缺少新审查记录被追溯判失败。
5. 从写到落地的请求授权在既定目标和已商定方案内继续本地实施，不自动授权提交、推送、付费调用、数据库高风险变更或生产发布。用户明确授权的操作不反复索取同一批准；缺少的权限只在真实边界处暂停。

进入实施时按 `adr-implementation` 的工作树选择规则处理；写作和方案审查阶段不触发这项询问。

## 连续推进与停止

完整链路在每个门禁通过后继续下一阶段；进度说明是中途更新，不是默认停点。仅在用户限定阶段或要求停止、重大未决选择、独立审查门禁无法满足、缺少实际必要权限/输入、或无法自行解决的阻塞时停止。最后分别报告“ADR 已写”“方案审查通过”“本地实现通过”“已提交”“已推送”“已发布”的真实证据，不把一个阶段的通过冒充全链完成。

本总控不能授予权限、覆盖项目规则或代替独立审查。按用户请求及既有授权推进对应阶段，常规技术细节可自行判断；扩大目标或代用户决定重大取舍须有明确授权，不因选中 Skill 自动获得。
