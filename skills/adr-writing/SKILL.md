# ADR 撰写

本组件负责从需求到可审查的架构决策草案，不把写完文档当作实施授权或审查通过。项目已有 ADR、来源、阶段和测试格式优先；仅在项目缺少格式时使用 [ADR 后备提纲](templates/adr-outline.md) 与 [阶段/测试后备合同](templates/phase-test-contract.md)。

用户要求先写 ADR 时，先形成可审查的 ADR；仅在实施已获授权且必要前置条件满足后进入实施。单独要求写 ADR 不自动授权改代码或发布，也不把 ADR 强加给未要求的普通修改。

## 输入与决策权

1. 先保存用户原话或可恢复的来源锚点、日期和附件留存状态；短需求可内嵌 ADR，长需求或多个 ADR 共用同一来源记录。之后的澄清以日期追加，不改写原话。敏感材料只保留批准的脱敏定位。
2. 区分用户已决定、仓库已证实、智能体建议和仍待决定的事项。新且未定的重大取舍要同用户讨论目标、备选方案、代价、迁移、阶段及验收；用户已明确决定的事项不反复询问。对本应由用户决定的重大技术取舍，仅在用户明确授权自主决定时才可代为选择，并标注“代理依据授权决定”；产品目标、计费或数据政策等超出授权的决定仍须用户确认。只要求草案时，把未决项标为 `PROPOSED`。
   对需要用户决定、又不能从现有授权或证据确定的未决问题，尽早直接询问并说明影响；等待答复时继续不依赖该决定的工作，不把推荐项或沉默当作批准。日常技术细节按已有授权自行处理。
3. 在确定新增职责位置前，取得本次受影响范围的架构检查证据；可切换到 `adr-check`，也可引用同等质量的项目记录。证据不足时不编造文件归属或“God Object”结论。

## 决策文档

- 以用户原话及后续明确授权为依据，在 ADR 或既有阶段记录中固定可核对的范围基线：本次目标与非目标、可复用的现有能力、须保持的旧行为与权限/数据/计费不变量，以及验收和收口条件；后续已授权的范围变化保留来源。对受影响旧功能制定相称的回归验证，不另建重复文档。范围不明且无法依据现有授权合理决定时向用户澄清；已明确的决定不重复询问。

- 在提出新增实现前，按本次影响范围检索现有业务逻辑、组件、接口和功能及其实际用法；优先复用适用能力，或通过合理组合、兼容扩展满足需求。ADR 记录候选及采用方式；确需新增时说明查过什么、具体能力缺口及不复用的原因。复用仍须保持旧行为和边界，避免引入不必要的耦合。

- **先判断新增机制是否必要**：从满足目标与既定安全约束的最小改动出发；新增服务、持久状态、写入者或接管机制时，说明它解决的具体缺口，并比较复用或扩展已有入口的办法。合理复用不足时可以新增；不因用户说“自动化”就默认多消费者或另建调度系统。修复意见使机制持续增加时，重新比较较小可行方案，不只沿旧方案叠加补丁。

- 为用户可见要求和技术约束分配稳定的 `FR` / `TR` 标识，映射“来源锚点 → 决策 → 阶段 → 测试或验收谓词”。代理提出的要求标明是建议，不冒充用户确认。
- 写出当前架构基线、被影响模块的既有职责与依赖、新职责归属、明确禁止继续堆入的模块、接口与边界测试。体积只是信号，需结合行为和耦合；范围外旧债记录风险，不塞进本次实施。
- 记录推荐方案、真正有区别的备选方案、后果、兼容/迁移/回退、权限与外部成本边界、阶段依赖、完成条件。系统不能靠模型口头宣称完成；验收要有可观察证据。
- 实施方案需要隔离工作树时，在阶段计划中按项目规则和运行环境写明位置、起点与恢复方式，确保目标可访问，并保留现有工作。
- 一份事实只设一个所有者：ADR 管决策与计划映射，阶段记录管进度，测试合同管意图，验收记录管结果。链接现有项目记录，不默认创建空模板。

## 作者自查与修订

首次送审和实质修订后，在现有 ADR 中完成以下核对；只记录影响决策的场景、结论与缺口，不另设阶段、审批或必交自查报告。简单变更可用几句话，不机械展开全套异常清单。

- **沿实际链路推演**：用具体输入走过正常路径和受影响的旧路径。涉及定时/事件时补无事件、重复或过期输入；涉及并发/副作用时补重叠执行、中途退出和结果不明，追踪实际副作用由谁发出、谁能阻止；涉及持久化/累积资源时补重启、部分写入与容量失败。只展开本次存在的风险；写出触发条件、行为和可观察结果，不能仅凭出现“锁、幂等、回退”等术语判定安全。
- **验收必须可执行**：逐项核对输入来源、环境、允许操作、预期结果和失败判据。区分可构造样本与不可控真实事件；没有事件时明确本阶段能证明什么、缺什么。演练不得越过授权或污染旧流程；查清所需历史证据是否实际留存。
- **修订同时守住旧要求**：处理意见后，沿受影响的定义、检测粒度、调用方、权限、阶段和验收核对前后对应关系；防止新增一层检测却删除原层、替换定义后遗留旧引用、共享入口遗漏普通调用方。对照累计范围，保留仍有效的要求，完成后重读当前完整方案再固定指纹。自查不产生独立 `PASS`，仍按授权交给 `adr-review`。

## 交接与停止

文档完成后检查链接和矛盾，标明“待 `adr-review` 独立审查”。直接点名只用 `adr-writing` 时交付 `PROPOSED` 草案，不暗中调用其他组件；由 `adr-workflow` 接管的完整 ADR 流程则在写作后衔接审查。未完成独立审查或仍有重大未决项时，不得声称方案已通过。仅写作的请求到此结束，不启动代码、提交、推送或部署。
